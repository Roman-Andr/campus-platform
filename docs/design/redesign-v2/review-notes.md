# Проверка визуальных черновиков

26 тематических листов / 78 экранных представлений подготовлены встроенным
image_gen по одному выбранному референсу. Полные промпты сохранены рядом.
Изображения отправляются пользователю в Telegram по готовности и связываются
с ответственными задачами. В репозитории лежат копии WebP полного разрешения
для доставки; исходные PNG сохранены отдельно, без кадрирования и замены.

## Перед реализацией

- Источник правил — текущие domain/application/API и функциональная issue,
  а не текст на сгенерированной картинке. Примерные даты, ёмкости, фамилии,
  состояния и числовые лимиты не копируются в код.
- #376 уточняет читабельность, точные размеры, все состояния и варианты
  ролей. Примерная подпись «надёжный участник» не является новой функцией;
  в runtime используются только разрешённые серверные показатели.
- Optional consent, доступ к переписке, подтверждённая почта и privacy
  формулируются точно по существующим документам и API. Визуальный референс
  не утверждает тексты документов и не проверяет личность.
- Вместо переписывания стандартных библиотечных контролов сначала
  применяются theme и общие составные компоненты. Каталог должен показать
  реальные focus/disabled/loading/error, а не только статичные образцы.
- В каждом реальном сценарии проверяются keyboard insets, Back, scroll,
  form preservation, идемпотентность, stale state и офлайн-переходы.
- Контраст восьми палитра/яркость сочетаний, TalkBack и крупный текст
  проверяются на реализованных компонентах. В этом PR таких проверок нет.
- Анимации, частота кадров и lifecycle не оцениваются по PNG; результаты
  профилирования относятся к #382 и итоговой #407.

Генерация картинок не закрывает #376 и задачи реализации. Текущий PR
добавляет проверяемый реестр и визуальную основу для дальнейшей проработки.
