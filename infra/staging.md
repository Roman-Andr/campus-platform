# Тестовый стенд через VPS

Принятый формат ручного тестирования: все сервисы Campus работают на
локальной машине разработчика, а небольшая VPS служит публичной точкой
входа. Покупать отдельную мощную VPS для этого стенда пока не требуется.

## Схема

```text
Телефон / браузер
  → campus.romanandr.ru:443
  → VPS rs.romanandr.ru (195.250.124.35)
  → Xray/REALITY → nginx (HTTPS)
  → 127.0.0.1:18880 на VPS
  → обратный SSH-туннель
  → 127.0.0.1:18880 на локальной машине
  → Caddy → API / Centrifugo / Flutter web
```

`campus.romanandr.ru` и `storage.campus.romanandr.ru` направлены на IP
VPS. Второй домен обслуживает приватное S3-хранилище RustFS; nginx и
Caddy сохраняют исходный Host, поскольку он входит в подпись ссылок.
TLS завершается на nginx; сертификат Let's Encrypt обновляется
существующим acme.sh на VPS. WebSocket проходит через оба прокси.
Исходный IP передаётся через доверенную цепочку прокси для лимитов входа.

Туннель инициирует локальная машина, поэтому ей не нужны белый IP и
проброс портов роутера. На VPS используется отдельный SSH-пользователь
`campus-tunnel`: разрешены только обратные пробросы на loopback-порты
18880 и 18825. Существующие сайт и Xray продолжают работать.

## Локальное развёртывание

Первый стенд настроен 14 ноября 2026 года на машине RomanAndr (Linux/WSL):

- Каталог: `/home/roman/.local/share/campus-stage/`.
- `source/` — отдельный снимок исходников; коммит записан в
  `SOURCE_COMMIT`. Изменения рабочего репозитория автоматически туда
  не попадают: перед следующей проверкой новых функций снимок и сборки
  нужно обновить отдельно.
- `source/infra/compose.stage.yaml` — локальные дополнения к Compose;
  `source/infra/.env` — отдельные секреты, не хранящиеся в Git.
- Проект Compose и постоянные тома имеют префикс `campus-stage`.
  База, Redis и хранилище работают локально, не на VPS.
- `campus-stage.service` и `campus-tunnel.service` — пользовательские
  сервисы systemd. Туннель автоматически переподключается при обрыве.
- На VPS конфигурация nginx находится в
  `/etc/nginx/sites-available/campus.conf`.

После тестирования стенд останавливаем. Автозапуск при старте WSL
отключён, чтобы стенд не занимал ресурсы без необходимости.

Запустить сохранённый стенд вручную:

```sh
systemctl --user start campus-stage.service campus-tunnel.service
systemctl --user status campus-stage.service campus-tunnel.service
```

Остановить и отключить автозапуск:

```sh
systemctl --user disable --now campus-tunnel.service campus-stage.service
```

Посмотреть логи API:

```sh
podman logs --tail 100 campus-stage-api-1
```

Остановка сохраняет базу и фотографии. Не использовать `down -v`, если
данные должны остаться. Машина, WSL и интернет должны работать всё время
тестирования. При выключенном туннеле публичный домен может отвечать 502.

## Регистрация и тестовая почта

Приложение: <https://campus.romanandr.ru>. Для нового тестового аккаунта
можно указать отдельный вымышленный адрес `@edu.hse.ru` или `@hse.ru`,
запросить код, затем заполнить имя, согласия и профиль.

Настоящие письма не отправляются: SMTP направлен в Mailpit. На локальной
машине письма доступны по <http://localhost:18825>. С телефона вводим код,
прочитанный на компьютере. Mailpit публично не открыт.

При необходимости открыть почту с другого компьютера через VPS:

```sh
ssh -N -L 8025:127.0.0.1:18825 root@rs.romanandr.ru
```

Затем открыть <http://localhost:8025>. Письма Mailpit не сохраняются при
пересоздании его контейнера; можно запросить новый код.

## Особенности конфигурации

- Используются только тестовые данные; справочники и документы согласий
  загружены демонстрационным seed.
- Бакет RustFS приватный, CORS разрешает браузерный origin приложения.
- Веб-клиент собран с
  `--dart-define=CAMPUS_API_URL=https://campus.romanandr.ru` и
  `--no-web-resources-cdn`.
- В конфигурации контейнеров API, воркера и планировщика домены Campus
  закреплены через `extra_hosts` за IP VPS из-за старых DNS-ответов WSL.
  При смене IP эти записи нужно обновить.
- После создания DNS-записей может мешать отрицательный кэш. На VPS его
  очищает `resolvectl flush-caches`; в Windows — `ipconfig /flushdns`
  из терминала администратора.

При первичной настройке проверены публичный HTTPS, вход по коду из
Mailpit, WebSocket (HTTP 101), загрузка фото по подписанной ссылке,
обработка фото до `ready` и восстановление туннеля после перезапуска.
